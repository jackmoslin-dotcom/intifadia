# تسليم تحديث INTIFADIA — 24 أكتوبر 2026

التحديث جاهز للتحقق والنشر من حساب المالك. لا يعني تجهيز الملفات تطبيقها على قاعدة الإنتاج أو نجاح نشر Vercel. لم تُعدّل أسرار البيئة أو بيانات الإنتاج.

## تطبيق SQL على المشروع الموجود

1. تأكد من مشروع Supabase المرتبط بـ INTIFADIA، ومن توفر نسخة احتياطية وفق إعداداتك الحالية.
2. افتح SQL Editor وانسخ **كامل** `supabase/migrations/003_civic_update.sql` ونفّذه. يلزم وجود الترحيلين 001 و002 مسبقاً؛ **لا تعِد تطبيقهما على الإنتاج** ولا تستخدم reset. الترحيل 003 داخل transaction وقابل للإعادة ويحافظ على الردود والأدوار وإعدادات الاحتفاظ والإعلان المعدّلة.
3. تحقق دون قراءة إجابات المشاركين:

```sql
select count(*) as question_count from public.question_definitions; -- 36
select public.public_event();
select relname, relrowsecurity from pg_class
where oid in ('public.event_announcement'::regclass,'public.participation_counts'::regclass);
-- relrowsecurity يجب أن تكون true للجدولين
```

4. فعّل حساب المالك باتباع `docs/OWNER_ACCESS.md` وملف `supabase/owner-access.sql` المنفصل. هذا الملف ليس ترحيلاً تلقائياً؛ يجب استبدال UUID فيه بالحساب الصحيح.

## إكمال النشر على Vercel

1. من المستودع شغّل `npm ci` ثم `npm run typecheck` ثم `npm test` ثم `npm run build`. لا تغيّر قيم متغيرات البيئة الحالية إن كانت صحيحة.
2. بعد تطبيق 003، ادفع التحديث المعتمد إلى الفرع المرتبط بمشروع Vercel أو انشره من حسابك. لا تدفع بيانات اختبار إلى الإنتاج.
3. يحتفظ المشروع بإعداد Build Output API: أمر البناء `npm run build`، والمخرجات `.vercel/output`. تُنفَّذ الدالة المجمعة `functions/api.func/index.cjs`. لا تضف `api/index.ts` أو `api/index.js` منافسة. لا تتجاوز إعداد المستودع بمجلد `dist` في لوحة Vercel.
4. تحقق من حالة Ready وسجل البناء، ثم افتح `/api/config` و`/api/event` و`/api/results` على رابط الإنتاج. يجب ألا يظهر `FUNCTION_INVOCATION_FAILED`. لا يعني إخفاء نتائج أقل من حد الخصوصية وجود عطل.
5. افتح الصفحة الرئيسية على الهاتف وسطح المكتب، وتحقق من الموعد والشعار وروابط تيليجرام، ثم سجّل دخول المالك وأكمل TOTP واختبر عرض المجاميع والإعدادات. لا تعدّل حالة الإعلان الحقيقية لمجرد الاختبار.
6. اختبر دورة الإرسال الفعلية مع Turnstile على بيئة Preview وقاعدة اختبار منفصلة. الاختبارات المحلية لا تثبت نجاح الاتصال بقاعدة الإنتاج أو Supabase Auth الفعلي. لا يُعلن نجاح النشر قبل التحقق من رابط الإنتاج.

## تفاصيل البيانات والخصوصية

- بقيت معرّفات وخيارات الأسئلة الأصلية الـ35 وملفا الترحيل 001 و002 دون تغيير. السؤال 36 اختياري، نعم/لا، ومعرّفه `demonstration_intent_2026_10_28`. تقبل قاعدة البيانات الردود القديمة بدونه.
- تُحفظ إجابة السؤال 36 ذرّياً في عدادات يومية خاصة دون UUID للمشارك أو رابط إلى صف إجاباته أو بياناته الديموغرافية. لا توجد قائمة حضور. إعادة الطلب بنفس المعرّف لا تضاعف العداد، ولا تغيّر النية حتى إذا غيّر العميل خياره في إعادة الطلب.
- مقام نسب السؤال 36 هو مجموع إجابات نعم/لا الصالحة فقط. تُحجب المجاميع العامة والنسب معاً إذا كانت إحدى الفئات المأهولة أصغر من حد الخصوصية. الحد الحالي محفوظ، ولا يقل عن خمسة وفق القيد القائم.
- يرى المالك والمحلل المجاميع المخوّلة دون حد النشر العام. تعرض الأسئلة النصية نسبة الإجابة دون نشر النصوص؛ تخضع النصوص للمراجعة القائمة قبل النشر. لا يجري تحليل سياسي للأفراد.
- لا يخزّن المخطط المسودات أو الاستبيانات غير المرسلة؛ لذلك تظهر هذه الفئة على أنها غير متتبعة، ولا تُختلق أعداد مكتملة/غير مكتملة.
- تبقى سياسة الاحتفاظ وإجراء الحذف المخوّل القائم. تُحذف عدادات النية على مستوى اليوم الكامل، وقد تبقى حتى يوم إضافي بسبب عدم الاحتفاظ بأوقات فردية. قد يختلف مجموع النية عن مجموع الردود قرب حد انتهاء الاحتفاظ.
- حالة الإعلان قابلة للتعديل بواسطة المالك بين مقترح ومعلن ومؤجل وملغى. التاريخ ثابت لاتساق نص السؤال؛ تغيير الموعد إلى يوم آخر يتطلب سؤالاً/نسخة جديدة، ولا يجوز إعادة تفسير الإجابات القديمة.
- الموعد معلن من المنظم وفق إفادته، ولا يدعي التطبيق تصريحاً حكومياً. عند تعذر تحديث الحالة تظهر ملاحظة تطلب مراجعة القناة الرسمية.

## حدود التحقق

اختبارات PostgreSQL محلية عبر PGlite ببيانات اصطناعية وبدائل اختبار لدوال Auth. لا تُنسخ بدائل Auth إلى Supabase. يلزم تحقق المالك من جلسة Auth الحقيقية وMFA وTurnstile وPostgREST بعد تجهيز الخدمات. لم يُجرَ reset أو تعديل على قاعدة الإنتاج، ولم تُرسل بيانات مشاركين إلى الاختبارات.

## نتائج التحقق المحلي

- `npm run typecheck`: ناجح.
- `npm run build`: ناجح، بما فيه بناء الواجهة وتجميع API ومراجعة الواردات المحلية. تحذيرات تعليقات Zod و`supports-color` الاختياري غير مانعة.
- `npm test`: نجح 103 اختباراً، تشمل الترحيل القابل للإعادة وحفظ الردود القديمة والتحقق من 36 سؤالاً وحساب المقام وحجب الفئات والصلاحيات وMFA والتصدير والاحتفاظ.
- `npm run test:e2e`: نجح 16 اختباراً على الهاتف وسطح المكتب، بما فيها RTL وعدم تجاوز عرض الشاشة والأسئلة الاختيارية والإعلان وتيليجرام وفحص axe لإمكانية الوصول. راجعت صورتَي المعاينة الناتجتين.
- نسخ ملف `index.cjs` وحده إلى مجلد مؤقت وتشغيله: استجاب `/api/config` برمز HTTP 200 دون ملفات المصدر أو `node_modules` بجانبه.
- أُصلحت أخطاء SQL وتوقع عدد الأقسام التي ظهرت في التشغيل الأول؛ لا توجد اختبارات فاشلة في التشغيل النهائي.
- لا تحقق حيّاً من Supabase Auth/Turnstile أو نشر إنتاج جديد؛ ما زالت خطوات المالك مطلوبة.
