# انتفاضة الوعي الشبابي — نسخة مراجعة خاصة

تطبيق عربي من الصفر: React وTypeScript للواجهة، Express للخادم، وSupabase PostgreSQL للتخزين والمصادقة. هذه النسخة **للمراجعة ببيانات اصطناعية فقط**. لم تُنشر على الإنترنت، ولا يجوز دعوة مشاركين حقيقيين قبل مراجعة مستقلة للأمن والخصوصية.

## تشغيل سريع دون مفاتيح

ثبّت Node.js 24، ثم افتح PowerShell في هذا المجلد:

```powershell
npm ci
Copy-Item .env.example .env
npm run dev
```

افتح `http://127.0.0.1:4317`. يمكنك مراجعة التصميم وجميع أسئلة الاستبيان والتنقل دون إعداد خدمات خارجية. الإرسال والإحصاءات وتسجيل دخول الإدارة تتوقف بوضوح حتى تهيئة الخدمات؛ لا توجد قاعدة وهمية أو أرقام مصطنعة.

للمعاينة من النسخة المبنية:

```powershell
npm run build
$env:NODE_ENV = 'production'
npm start
```

الخادم يستمع على loopback فقط. إن كان المنفذ مستخدماً، غيّر `PORT` و`APP_ORIGIN` معاً في `.env`. لا تشغّل خادم التطوير مكشوفاً للإنترنت.

## إعداد قاعدة بيانات اختبار خاصة

1. أنشئ مشروع Supabase منفصلاً للتجربة، ولا تستخدم مشروع إنتاج أو بيانات أشخاص حقيقيين.
2. من SQL Editor نفّذ `supabase/migrations/001_core.sql` ثم `002_questions.sql` بالترتيب. يجب تنفيذ كل ملف كاملاً، مرة واحدة على قاعدة جديدة. لا تعطّل RLS.
3. ضع عنوان المشروع ومفتاح anon العام ومفتاح service-role السري في `.env`. المفتاح السري يستخدمه الخادم فقط. لا تستخدم بادئة VITE للمتغيرات السرية ولا تنسخها إلى الواجهة أو Git.
4. أنشئ حساب المسؤول من لوحة Supabase Auth. عطّل التسجيل العام؛ هذه الواجهة لا تسمح بإنشاء حسابات.
5. انسخ UUID للحساب الذي أنشأته، ثم نفّذ في SQL Editor بعد استبدال القيمة بمُعرّف حسابك:

```sql
insert into public.admin_roles(user_id, role)
values ('REPLACE_WITH_REAL_ADMIN_UUID', 'owner');
```

لا تنفّذ المثال حرفياً. الأدوار: `owner` للإعدادات والحذف وكل الأقسام، `moderator` لمراجعة النصوص، `analyst` للإحصاءات المجمعة والتصدير. لا تمنح المستخدم صلاحية service-role.

6. افتح `/admin/login` وسجّل الدخول. في أول مرة، اربط تطبيق مصادقة TOTP عبر QR، ثم أدخل الرمز. وظائف الإدارة ترفض مستوى `aal1` وتطلب `aal2` داخل PostgreSQL، وليس في الواجهة فقط. تُحفظ رموز الجلسة في ذاكرة المتصفح، وتُفقد بعد إعادة التحميل؛ سجّل الدخول مجدداً.
7. أعد تشغيل الخادم بعد تغيير `.env`.

## التحقق الآلي وحد الإرسال

اضبط `TURNSTILE_SITE_KEY` و`TURNSTILE_SECRET_KEY` من حساب Cloudflare مخصص للاختبار، واسمح باسم المضيف الموجود في `APP_ORIGIN`. يتحقق الخادم من نجاح الرمز والمضيف والإجراء `survey`. لا يوجد تجاوز للتحقق داخل التطبيق. لا تستخدم مفاتيح الاختبار في بيئة تستقبل أشخاصاً حقيقيين.

أنشئ قيمة عشوائية سرية طويلة لـ `RATE_LIMIT_SECRET` (٣٢ بايت أو أكثر) عبر مدير أسرار. تستخدم لبصمة عنوان الشبكة المتغيرة كل ساعة؛ لا تُخزّن البصمة في سجل الإجابات. الحد عشرة طلبات صحيحة البنية في الساعة للبصمة، بما فيها المحاولات التي يفشل تحققها الآلي. تعطل قاعدة الحد يؤدي إلى رفض الإرسال مؤقتاً. اضبط `TRUST_PROXY_HOPS` فقط إذا كان التطبيق خلف وكيل موثوق ومعروف؛ القيمة الافتراضية صفر.

اضبط `CONTACT_EMAIL` إلى عنوان موثق تابع للجهة المشغلة لإظهار رابط البريد في صفحة التواصل. لا يوجد بريد افتراضي مختلق أو خدمة إرسال بريد داخل المشروع.

## محتويات المشروع

- `src/survey.ts`: مصدر الحقيقة للأسئلة الـ٣٥ وخياراتها وقواعدها؛ الستة أقسام موزعة ٦/٦/٦/٦/٦/٥.
- `docs/SURVEY.md`: دليل عربي لكل سؤال، بما فيه المعرف والتخزين والتجميع والشرط.
- `src/main.tsx` و`src/style.css`: صفحات الواجهة وRTL ونسخة الهاتف.
- `server/`: مسارات API والتحقق والأمان؛ لا تخزين بديل داخل الخادم.
- `supabase/migrations/`: الجداول والقيود والوظائف والصلاحيات وRLS.
- `tests/`: Vitest وPostgreSQL عبر PGlite واختبارات Playwright.
- `docs/PRIVATE_STAGING.md`: خطوات إعداد ومراجعة البيئة الخاصة.
- `docs/SECURITY_PRIVACY_CHECKLIST.md`: قائمة مراجعة الأمن والخصوصية.
- `ACCEPTANCE_REPORT.md`: النتائج الفعلية والقيود وخطة الاستكمال.

## الصفحات

`/`، `/survey`، `/results`، `/demands`، `/about`، `/goals`، `/methodology`، `/privacy`، `/contact`، `/admin/login`، `/admin`، `/admin/analytics`، `/admin/moderation`، `/admin/settings`.

صفحات الإدارة تعرض بوابة الدخول للزائر؛ البيانات والعمليات لا تُتاح إلا بعد تفويض الخادم وقاعدة البيانات. لا توجد روابط Telegram غير موثقة.

## الاختبارات

```powershell
npm test
npm run typecheck
npm run build
npm audit
npx playwright install chromium
npm run test:e2e
```

اختبارات المتصفح تشغل نسخة الإنتاج آلياً على `127.0.0.1:4321` وتغلق خادمها بعد الانتهاء؛ يجب بناء المشروع أولاً. قد تحتاج أذونات شبكة لتنزيل الحزم وتشغيل loopback. اختبارات SQL تستخدم PostgreSQL مبنياً لـ WebAssembly (PGlite) مع بدائل اختبار محلية لدوال `auth.uid()` و`auth.jwt()`؛ هذا لا يثبت عمل Supabase Auth أو PostgREST أو توقيع JWT الحقيقي. لا تستخدم بدائل auth الموجودة في الاختبارات في أي قاعدة خارجية.

بعد تعديل تعريف الأسئلة، شغّل `npm run db:generate` لتحديث ملف الأسئلة ودليلها. بعد نشر قاعدة لأول مرة، أنشئ ترحيلاً جديداً بدلاً من إعادة تطبيق ملفات إنشاء الجداول. احتفظ بمعاني المعرفات والرموز ثابتة.

## قواعد النشر والاحتفاظ

لا تُنشر النصوص تلقائياً. يقرأ المشرف النص الخاص ويكتب نسخة آمنة ويؤكد مراجعتها. يمكن رفض النص أو سحب نشره لاحقاً. التصدير CSV يحتوي المجاميع الآمنة فقط ويعالج بادئات صيغ الجداول.

تُحجب توزيعات السؤال بالكامل عند وجود فئة مأهولة أصغر من حد النشر؛ هذا يقلل الاستدلال بالطرح. لا توجد تقاطعات ديموغرافية. لا تعني الحماية إخفاء هوية مضموناً، ولا تمنع كل استدلال عبر الزمن.

الاحتفاظ الافتراضي ١٨٠ يوماً، قابل للضبط ٣٠–٧٣٠. في صفحة الإعدادات، تؤكد عملية حذف البيانات المنتهية بكتابة `DELETE EXPIRED`. يجب على المشغل تشغيلها دورياً؛ لا توجد مهمة حذف مجدولة خارجية مهيأة. الحذف يشمل المطالب التابعة، وليس نسخ المزود الاحتياطية. يجب توثيق سياسة النسخ والاستعادة قبل أي إطلاق.

الصورة المحلية مأخوذة من المرجع الذي أرفقه صاحب المشروع. يجب التحقق من حقوق استخدامها قبل إطلاق عام. لا تدل الصورة على واقعة موثقة أو عدد مشاركين فعلي.
